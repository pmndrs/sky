`SkyAtmosphereBaker` (`import { SkyAtmosphereBaker } from '@pmndrs/sky'`) is
what [`Sky`](./sky) constructs and drives internally
(`sky.baker` — always available). Reach for it directly when you need
control `Sky` doesn't expose: custom dirty-flag management, direct LUT
access, or building your own facade.

Source: `src/sky/SkyAtmosphereBaker.ts`.

## Architecture

A **split-scene bake-first** design. The baker owns a private sky scene
containing a single `SkyAtmosphereMesh`, three LUTs (Transmittance →
MultiScatter → SkyView, see [LUTs](./luts)), a `CubeRenderTarget`, a
`CubeCamera`, and a `PMREMGenerator`. Optionally (default on) it also owns
a fourth LUT, the aerial-perspective 3D froxel volume.

Call `baker.update()` once per frame; it cascades dirty flags and only
re-runs the pipeline stages whose inputs actually changed. The main scene
consumes `baker.environmentTexture` (PMREM-filtered) for IBL and
`baker.texture` (raw cube) for `scene.background`.

```js
new SkyAtmosphereBaker(renderer, options?)
```

## Shader compilation

`await baker.compileAsync()` compiles the three LUT passes, the cube capture
and (three r186+) the aerial-perspective pass without blocking, so the first
`update()` finds their pipelines ready. Each pass is compiled against its own
render target, keyed the way the draw will be. Optional; see
[`Sky.compileAsync()`](./sky#shader-compilation) for why it matters on Windows.

## Dirty-flag semantics

The baker tracks four independent dirty flags so `update()` skips work
whose inputs haven't changed:

| Flag          | Set by                                                                                                                                                                                                                                                                                    | Triggers on next `update()`                                                  |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------- |
| `atmosDirty`  | `setAtmosphereParams(partial)`, when a value actually changed                                                                                                                                                                                                                             | Transmittance + MultiScatter + SkyView + cube bake + PMREM (full chain)      |
| `sunDirty`    | `setSun({ elevation, azimuth })`, when either value changed                                                                                                                                                                                                                               | SkyView + cube bake + PMREM (Transmittance/MultiScatter don't depend on sun) |
| `cubeDirty`   | The two above; `markCubeDirty()`; `setLook` / `setSunColor` / `setSkyLuminanceFactor` / `setMirrorBelowHorizon`; a `displayScale` change (`Sky` only); and from `setCamera`: altitude moved more than 100 m (or 2 % of altitude, if larger) or the local sun zenith cosine drifted > 1e-3 | Cube bake + PMREM only                                                       |
| `cameraDirty` | `setCamera(camera, opts)`, when altitude moved more than 1 m (or 0.5 % of altitude, if larger) or the local sun zenith cosine changed                                                                                                                                                     | SkyView (viewHeight) — the AP LUT is refreshed separately, see below         |

The `setCamera` thresholds compare against the state at the last SkyView
render / cube bake, not the previous frame, so slow drift still re-bakes
eventually. The altitude rule applies in flat and planet mode alike; the
zenith drift only happens in planet mode (local up tilts as you move).

`update()` is a no-op if nothing is dirty (apart from advancing a pending
`generator: 'three'` IBL refresh). This is why calling `sky.update(camera)`
every frame is cheap once the sun/atmosphere have settled — most frames it's
just a camera-height comparison.

### Renderer state

`update()` and `flushPmrem()` leave the renderer as they found it, so they can
be called in the middle of your own frame, with an MRT still active from a
G-buffer pass (`renderer.setMRT(mrt({ output, normal: normalView }))`). Every
internal draw (the LUT passes, the cube capture, three's PMREM generator)
runs with the MRT cleared, and your MRT, render target, active cube face and
mip level are restored afterwards. That holds when a draw throws, too: the
error propagates, the baker stays dirty so the next `update()` retries the
bake, and the sky-mesh uniforms the bake overrides (`showSunDisc`,
`showMoonDisc`, `mirrorBelowHorizon`) are put back. An idle `update()`
touches no renderer state. `updateAerialPerspective()` is a compute dispatch
and doesn't depend on any of it.

> **Note:**
> `updateAerialPerspective()` is **not** part of the dirty-flag system — the AP LUT's froxels are camera-relative, so it
> must re-render every frame the camera moves, regardless of any other dirty state. Call it explicitly each frame if
> you've wired `applyHaze`.

## Environment (PMREM) refresh

"PMREM" in the table above is the IBL refresh: the cube prefiltered into one
level per roughness, which is what `environmentTexture` holds. The baker has
two ways to do it, chosen by `pmrem.generator`.

### `generator: 'sky'` (default): every change, in the same frame

On the WebGPU backend the baker re-filters the IBL with its own compute
prefilter (`SkyPmrem`) on every sky change, in one compute pass instead of
three's six render passes per level. A moving sun or a scrubbed time-of-day
slider updates reflections in the same frame as the background.

- **three r187 and later:** three's own algorithm (GGX filtered importance
  sampling on the sharp levels, exhaustive integration on the rough ones), so
  the output matches three's generator. About 0.9 ms instead of about 4.5 ms
  (256 cube, Apple M-series).
- **three r185/r186:** the PMREM is a CubeUV atlas. Each atlas level is
  filtered at the roughness three's material sampler reads it at. About 1 ms
  instead of 6.4 ms (r185) or 3.3 ms (r186). It is also much closer to the
  true GGX reflection than three's generator, whose levels don't match its
  own sampler, so mid and high roughness reflections look slightly different
  from `generator: 'three'`: softer horizons, and the ground's falloff kept
  on very rough surfaces.

```js
new Sky(renderer) // generator: 'sky', quality: 'three'
new Sky(renderer, { pmrem: { quality: 'fast' } }) // fewer samples on the sharpest level
```

Measured with the sun moving every frame (headless Chromium, Apple M-series):
`sky.update()` costs 1.0–1.1 ms mean and at most 2.2 ms, and the IBL always
matches the current sky.

On the WebGL backend (no compute) the baker uses three's generator as below.

### `generator: 'three'`: throttled and time-sliced

three's `PMREMGenerator` through `PmremScheduler`. A whole r185 bake is
about 6 ms and latency-bound, so a smaller cube barely helps. The scheduler:

- **throttles**: while the sky keeps changing, a refresh starts at most every
  `minInterval` ms (default 250). When changes stop, the final state is
  refreshed on the next frame, so the IBL never stays stale;
- **time-slices** (r185/r186): each refresh filters `levelsPerFrame`
  roughness levels per frame (default 1) into a scratch target and copies
  into the persistent target when complete. The result is identical to a
  whole bake. Slicing drives three's private per-level `PMREMGenerator`
  methods, which r187 removed: there every refresh is a whole bake, and a
  finite `levelsPerFrame` logs one warning;
- bakes the **first** environment synchronously, so frame one has IBL.

```js
new Sky(renderer, { pmrem: { generator: 'three', minInterval: 250, levelsPerFrame: 1 } })
new Sky(renderer, { pmrem: { generator: 'three', minInterval: 0, levelsPerFrame: Infinity } }) // whole bake per change
sky.flushEnvironment() // finish any pending refresh now (screenshots, hard cuts)
```

Measured with the sun moving every frame on r185: a whole bake per change
cost 7.7 ms mean / 17 ms max per update; the defaults cost 1.0 ms mean /
3.1 ms max, but the IBL lags the background by up to `minInterval` plus
about ten frames.

Either way, `environmentTexture` keeps the same texture object from the first
bake until `dispose()`. `baker.flushPmrem()` (what `sky.flushEnvironment()`
calls) finishes any pending or in-flight refresh immediately.

### Options and classes

| `pmrem` option   | Default   | Notes                                                                                                                                  |
| ---------------- | --------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `generator`      | `'sky'`   | `'sky'`: compute prefilter on every change (WebGPU; falls back to `'three'` on WebGL or an unknown PMREM layout). `'three'`: as above. |
| `quality`        | `'three'` | `'sky'` only. `'fast'`: 96 samples on the sharpest level, ~35 % cheaper on r187+, saves little on r185/r186.                           |
| `minInterval`    | `250`     | `'three'` only. Milliseconds between refreshes while the sky keeps changing; `0` refreshes on every change.                            |
| `levelsPerFrame` | `1`       | `'three'` only, r185/r186 only. `Infinity` bakes the whole PMREM in one frame.                                                         |

The baker builds this from `SkyPmrem`, exposed as `baker.pmrem`. All three
pieces are exported for custom facades:

| Export                                                                             | Notes                                                                                                                                                                                                                                                                                                              |
| ---------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `new SkyPmrem(renderer, pmremGenerator, cubeTexture, SkyPmremOptions)`             | `markDirty()` after each cube bake, `tick()` once per frame, `flush()`, `dispose()`; `.texture` / `.target` (`null` before the first bake). `.mode` stays `'three'` until the compute pipelines finish compiling after the first bake, then reads `'sky'`; `.layout` is `'cube'` (r187+) or `'atlas'` (r185/r186). |
| `new PmremScheduler(renderer, pmremGenerator, cubeTexture, PmremSchedulerOptions)` | three's generator, throttled and time-sliced. Same `markDirty` / `tick` / `flush` / `dispose` / `texture` / `target`; `minInterval` and `levelsPerFrame` are public fields you can change live.                                                                                                                    |
| `skyPmremPlan(maxLod, quality?)`                                                   | The per-level plan `SkyPmrem` runs on an r187+ cube PMREM: level 0 `{ fis: 0 }` (copy), the last three `{ integ: 16 }` (integrate the 16² mip), the rest `{ fis: 256 }` (`96` on level 1 with `'fast'`).                                                                                                           |

## Sun and camera

### `setSun({ elevation, azimuth })`

Degrees. `phi = 90 - elevation` (polar angle from +Y), `theta = azimuth`.
This `azimuth` is three's spherical theta, measured from +Z toward +X, which
is **counter-clockwise** seen from above. It is not a compass azimuth and
ignores `north`: `Sky.setSunDirection` converts a compass azimuth (clockwise
from north) to it, and `Sky.setSunDirection({ ..., raw: true })` passes it
through unchanged. Produces a Y-up world-space sun vector fed to the sky mesh, and separately
derives the Z-up sun vector the Sky-View LUT's internal frame expects (see
the Y-up/Z-up coordinate dance in the project's `CLAUDE.md` if you're
debugging a tilted horizon). Sets `sunDirty` and `cubeDirty`. A call with
the same `elevation` and `azimuth` as the last one returns early (no dirty
flags, no listeners), so re-applying an unchanged value every frame is free.

### `setCamera(camera, { planetCenter? })`

Feeds the main camera's height into the Sky-View LUT and mesh, and (if AP
is enabled) matrices into the AP LUT. Call every frame the camera moves.

- **Flat mode** (no `planetCenter`): `viewHeight = bottomRadius + camera.position.y * 0.001`
  — the legacy convention where world `y` is altitude.
- **Planet mode** (`planetCenter` given): `viewHeight` is computed as true
  radial distance from `planetCenter`, and `cameraUp` becomes the radial
  direction instead of fixed `+Y`. See the
  [Planet-scale guide](../guides/planet-scale).

In planet mode, moving around the sphere tilts local "up", which changes
the _effective_ sun elevation relative to the camera (the sun visually
"sets" as you fly around the globe even with a fixed world sun direction).
`setCamera` re-derives the Sky-View LUT's sun frame every call to account
for this, and forces a cube re-bake if the effective zenith drifted enough
to matter.

### `addSunListener(fn)` / `removeSunListener(fn)`

Subscribe to sun-direction changes — `fn(sunVec: Vector3)` fires at the end
of every `setSun()` call that changed the sun (vector passed by reference;
clone if you keep it).
`SkySun`/`SkyMoon` use this to keep their `DirectionalLight`s in lockstep
without per-frame polling. Returns an unsubscribe function.

### `addBakeListener(fn)`

Subscribe to cube re-bakes — `fn()` fires at the end of every `update()`
that re-baked the cube, i.e. after any change to what the sky shows: sun,
atmosphere, exposure (`luminanceScale`, through `markCubeDirty`), sun colour,
look, or a camera move large enough to change the baked sky (100 m, or 2 % of
the altitude). Read whatever you need from the baker in the callback. A
physical `SkySun` uses it to follow the exposure, atmosphere and altitude
without per-frame work. Returns an unsubscribe function.

## Atmosphere

### `setAtmosphereParams(partial)`

Merges `partial` onto the current `AtmosphereParams` (see
[Tuning the atmosphere](../guides/tuning-atmosphere) for the full shape)
and pushes updated values into the TSL uniform bundle. Sets `atmosDirty`
and `cubeDirty` — this is the expensive path, triggering a full LUT
rebuild on the next `update()`.

It returns early when every key in `partial` already equals the current
value (numbers by `===`, vectors by `.equals()`), so an object re-created
each render (React props) does not re-bake. A changed `sunAngularRadius`
also resizes the sun disc; an unchanged one leaves a size set through
`Sky.setSunDisc` alone.

### `markCubeDirty()`

Force the next `update()` to re-bake the cube + PMREM without touching the
LUTs. Useful if you mutated a sky-mesh uniform directly and bypassed the
baker's setters.

### `setMirrorBelowHorizon(flag)`

When `true`, the next cube bake folds below-horizon view rays to
above-horizon before sampling the LUT — the cube's (and hence
`environmentTexture`'s) lower hemisphere becomes a clean Y-mirror of the
sky instead of the LUT's lit-ground-albedo content. The **live** sky mesh
in the main scene (if you added one via `createSkyMesh`) is unaffected —
only the baked cube changes. Zero extra render passes; forces `cubeDirty`.

## Sky colour

Each of these is a uniform on the sky mesh, so it re-bakes only the cube +
PMREM (`cubeDirty`), never the LUTs — cheap enough to scrub per frame. The
haze picks up the same uniforms through `applyHaze`. `Sky`'s versions also
accept names and hex strings; the baker's take resolved values.

| Method                                  | Notes                                                                                                                                                                                                          |
| --------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `setLook(look \| null)`                 | Assign a resolved `Look` (`resolveLook('ghibli-day')`) or clear it. See the [Looks guide](../guides/looks).                                                                                                    |
| `setSkyLuminanceFactor(v)`              | Per-channel grade on the sky and haze, after the look (Unreal `SkyLuminanceFactor`). Excludes the sun, moon and star discs. `Vector3`, `{x, y, z}` or `[r, g, b]`.                                             |
| `setSunColor(v)`                        | Colour of the sun as a light source, linear RGB (`Vector3`, `{x, y, z}` or `[r, g, b]`). Tints the sky (before the look), the sun disc and the haze. See [Sun colour](../guides/tuning-atmosphere#sun-colour). |
| `addSunColorListener(fn)` → unsubscribe | `fn(sunColor: Vector3)` fires on every `setSunColor` (by reference; clone to keep). `SkySun` uses it to tint its light.                                                                                        |

### Keeping looks display-referred

A look's ramp is multiplied by `baker.sky.lookUniforms.displayScale`, which
must equal `1 / renderer.toneMappingExposure` (`1` under `NoToneMapping`) so
a look shows its authored colours at any exposure. `Sky.update` keeps it in
sync; with the baker alone, do it yourself before `update()`:

```js
const exposure = renderer.toneMapping === NoToneMapping ? 1 : renderer.toneMappingExposure
const displayScale = 1 / Math.max(exposure, 1e-4)
const u = baker.sky.lookUniforms.displayScale
if (u.value !== displayScale) {
  u.value = displayScale
  baker.markCubeDirty() // the cube holds the look
}
baker.update()
```

It has no effect while no look is set.

## Mesh access

### `createSkyMesh({ scale = 450000, showSunDisc = true })`

Returns a `THREE.Mesh` sharing the baker's internal geometry + material
(and therefore uniforms) — add it to your own scene for a _live_ sky that
updates every `setCamera` call instead of only on cube re-bake. Useful at
planet scale where altitude changes fast enough that the cube-bake cadence
alone looks stepped. `frustumCulled = false`; it is drawn like a game-engine
sky, after the opaque geometry (`renderOrder = SKY_RENDER_ORDER`, which is
`1_000_000` and exported from `@pmndrs/sky`), depth-tested at the far plane
with `depthWrite` off, so sky hidden behind geometry is never shaded.
Transparent objects still draw over it. If you add your own
`SkyAtmosphereMesh`, give it the same `renderOrder`.

The cube bake still runs on sun-dirty for IBL — `environmentTexture`
remains the recommended `scene.environment` regardless of whether you also
add a live mesh.

## Per-frame

| Method                              | Notes                                                                                                                                                                                                                                             |
| ----------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `update()`                          | Runs only the dirty pipeline stages. Call once per frame — cheap when nothing is dirty.                                                                                                                                                           |
| `flushPmrem()`                      | Finish any throttled or in-flight IBL refresh now (screenshots, hard cuts). `Sky.flushEnvironment()` calls this.                                                                                                                                  |
| `updateAerialPerspective()` (async) | Runs the AP compute pass unconditionally. ~1ms on a mid-range GPU. No-op if AP was disabled.                                                                                                                                                      |
| `dispose()`                         | Disposes all LUT render targets, the cube render target, PMREM target/generator, and the sky mesh's geometry/material. Does not remove the baker from any scene it wasn't added to directly — the baker manages its own private scene internally. |
